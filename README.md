# usage-autopilot

Claude の利用枠の**使用ペースと余りを見積もり、余る分で各プロジェクトを本人の代わりに自律的に進める**仕組み。

**運用データは含みません。** 仕組み（手順書・ツール・設計）と、そこから分かった実測値だけを公開しています。

> **いまの状態（2026-09-27）:** ここにある手順書・ツールは **2026-09-17 時点の版**です。
> 下の「仕組み」の**指揮役は 2026-09-20 に退役し、いまは動いていません**（実際には 2026-09-17 に、合図を待たずに止まっていました）。
> 配分の考え方と実測値はそのまま使えますが、指揮役を中心にした運行は、いまの作者の運用ではありません。

## 対応環境

**この仕組みそのものは、特定の環境でしか動きません。**持っていけるのは考え方と実測値のほうです。

| 部分 | 使える環境 | 前提になっているもの |
|---|---|---|
| 考え方・実測値（この README、`docs/design.md`） | どこでも | なし |
| 手順書（`prompts/`） | Claude Code のデスクトップアプリ | 定期タスク、ブラウザのペイン、セッションどうしのメッセージ |
| 道具（`tools/`） | Claude Code | 個人の利用枠（5時間枠・7日枠）と、claude.ai が画面に出している使用率。**非公開の仕組みで、予告なく変わりえる** |

**作者が動かしたのは、個人契約の Claude（Max プラン）だけです。**組織の契約（Team・Enterprise）や ChatGPT で、枠の形や使用率の取り方が同じかは確かめていません。

## 何のために作ったか

目的は2つあり、**どちらも同じ重さで扱っています。**

### 1. 余る枠を使い切る

利用枠はリセット時点で残っていても消えるだけです。その分を仕事に変えます。

### 2. 外部脳の再現度を試す

本人に聞かずに、[外部脳](https://github.com/feseisen/ai-context-kit)に書かれた判断基準だけで「本人ならこう判断する」を実行し、**どこまでトレースできたかを後から本人が採点できる状態**にします。

2があるため、**成果物と同じくらい「何をどう判断したかの記録」が重要**になります。
**判断ログのない実行は、テストとして価値がありません。**

判断ログの「本人の採点」を ○ / △ / × に書き換えると、それがそのまま外部脳の再現度の記録になります。

## 分かったこと（実測値）

この仕組みの副産物として測れたもの。**ここが一番使える部分かもしれません。**

### 会話の再開は、続けるより約17倍重い

| | 5時間枠の消費（中央値） |
|---|---|
| キャッシュが切れる前に続ける | **0.54%** |
| キャッシュが切れてから再開する | **9.35%** |

ある5時間枠では、**枠の47.8%が「再開コスト」だけ**で消えていました。

効くのは**再開の頻度より会話の大きさ**です。10万トークンあたり約2.3%。
つまり「こまめに新しい会話を立てる」より「**大きくなった会話を放置してから再開する**」方が高くつきます。

### 枠を食うのはキャッシュ書き込みと出力

キャッシュの**読み込み**はほとんど枠を使いません。書き込みと出力が使います。
長い文脈を持ち回ること自体は安く、**文脈を作り直すことが高い**、という構造です。

### 枠の換算

7日枠1%は5時間枠の約9〜10%に相当します（実測。記録が増えるほど `tools/budget.py` が自動補正）。

### 配分の方針は「薄く配る」より「まとめて使う」

当初は各枠に薄く配っていましたが、**動く時間にまとめて5時間枠を上限近くまで使い、それ以外は休む**方式に変えました。
理由は上記の再開コストです。薄く配ると、そのたびにキャッシュが切れた状態からの再開が発生します。

## 仕組み

| 役割 | どこで | モデル | やること |
|---|---|---|---|
| 使用率スキャン | 定期タスク（30分ごと） | 軽いモデル | 使用率を取って記録するだけ |
| **指揮役**（2026-09-20 に退役） | 専用セッション（同時に1つ） | **重いモデル** | 配分を判断し、案件セッションに指示、見張り、5時間枠ごとの報告書 |
| 案件セッション | 各リポジトリの既存セッション | 重いモデル | 指示を受けて区切りまで進め、見積もり・報告・判断ログを残す |

**モデルの線は、役割の名前ではなく「作業に取捨選択があるか」で引きます。**
配分は取捨選択なので、指揮役は軽いモデルにしてはいけません。

## 使うときの前提

そのままでは動きません。`data/` に置く運用データが要ります。

- 使用率は非公開の仕組みから取っているため、**予告なく変わりえます**
- パスは Windows のデスクトップアプリ前提で書かれています（`<ユーザー名>` は各自のものに読み替えてください）
- `data/` の形は `tools/` の各スクリプトを読めば分かります

**そのまま動かすより、考え方を持っていく方が向いています。**

## 分かっている地雷

実際にぶつかったもの。同じ構成を作る人の役に立つはずです。

- **デスクトップアプリの Claude Code は認証をアプリ側が持っていて、外部スクリプトから使用量APIを叩けない。** ステータスラインもデスクトップアプリでは実行されない
- **定期タスクのセッションからは、他のセッションにメッセージを送れない。** だから指揮役は開いたままのチャットセッションにしてある
- **自分が起動したのではないセッションを止める操作は、自動許可の判定で拒否される。** 設定で明示的に許可が要る
- メッセージは、相手が作業中でも作業の途中で読まれる。止める前に「区切りをつけて」と伝えられる
- 作業中・裏の処理が残っているセッションは、AIから削除もアーカイブもできない
- **メッセージ中に書いたスラッシュコマンドは実行されない**（ただの文字として届く）
- **ヒアドキュメントの中に書いた Python では、バックスラッシュが化ける。** バックスラッシュを含む編集は専用の編集ツールで行う
- 使用率スキャンの回が実行中のまま残ると、次の回が始まらない。タイムアウトの見張りが要る
- **自分の記録でしか生きていることを示さない仕組みは、止まると何も言わない。** この指揮役は止まってから4日間、誰にも気づかれなかった。外側に見張りを置く

## 自律実行の原則

- **判断基準の正典は外部脳。** ここには複製しない（複製すると必ず食い違う）
- **本人に聞きたいことが出ても止まらない。** 本人ならこう答えるだろうという想定で進め、判断ログに残す
- **本人にしかできないこと**（本人の耳や目で実物を確かめる、本人の素材を用意する、端末の設定を変える、採点）だけを本人待ちにする
- **中身の質が最優先。** 見積もりに作業を合わせない。ずれは記録して次に活かす
- 自律実行の指示に書くのは**自律実行のときだけ効くこと**に限る。大前提はグローバルな指示と設定で守る

最後の1つが効きます。**「第三者に公開しない」のような大前提を毎回のメッセージに書くと、必ずどこかで抜けます。**
グローバルな指示と設定に置き、メッセージ側には書かない。抜けがあればメッセージではなく設定の側を直します。
